面试题目

1、什么是进程、线程，有什么区别？

进程是资源分配和调度的基本单位，每个进程都有自己的独立内存空间，包括代码段、数据段、堆和栈等。

​ 每个进程都有一个唯一的进程标识符（PID）。

​ 进程间的内存通常是隔离的，一个进程崩溃不会影响其他进程。

​ 进程间通信（IPC）需要通过操作系统提供的机制实现，例如管道、消息队列、共享内存等。

线程是进程内的一个执行单元，是处理器调度和分派的基本单位，一个进程可以包含多个线程，这些线程共享相同的内存空间。

​ 同一进程内的线程共享进程的资源，如内存和文件句柄。

​ 线程间的通信比进程间通信简单得多，可以直接访问同一内存空间的数据。

​ 创建和切换线程的开销较小。

​ 由于共享内存，如果一个线程出现问题，可能会影响到整个进程内的其他线程。

2、多进程、多线程的优缺点

进程是资源分配的基本单位，而线程是处理器调度的基本单位。每个进程至少有一个线程，称为主线程，无论是多进程还是多线程，都可以实现程序的并发执行，提高程序的执行效率。

​ 对于多进程，由于每个进程拥有独立的内存空间，这意味着一个进程中的错误不会影响其他进程，进程间的隔离性较好，有助于提高系统的稳定性。并且由于进程间的数据隔离，我们不需要担心数据竞争和同步问题。但同时因为每个进程都需要独立的内存空间，意味着更多的内存消耗，进程创建和销毁进程的开销较大。进程间的上下文切换涉及切换内存空间和其他系统资源，开销较大。同时进程之间的通信需要通过操作系统提供的机制实现，例如管道，消息队列，共享内存等，多进程可以充分利用多核处理器的能力，适合处理计算密集型任务。

​ 对于多线程，同一进程内的所有线程共享内存空间，可以更容易地访问和修改共享数据，这使得线程间通信简单快捷。创建和销毁线程的开销较小。线程间的上下文切换开销较小。由于线程共享内存空间，存在数据竞争和同步问题和多个线程并发访问共享资源可能会导致资源争用问题，需要使用锁或其他同步机制来保护共享数据，这增加了编程复杂性，同时错误的同步机制可能导致死锁，多线程模型非常适合处理I/O密集型任务，如网络请求、文件读写等。

3、多进程、多线程同步（通讯）的方法

进程同步

1.管道

​ 命名管道：是在文件系统中作为特殊文件存在的管道，允许不相关的进程之间进行通信。使用mkfifo() 系统调用来创建一个命名管道，这个调用需要指定管道的路径，命名管道可以在任何两个进程之间使用，而不仅仅是父子进程。命名管道作为文件系统的一部分存在，直到明确删除它。

​ 匿名管道：临时的、只存在于内存中，通常用于相关联的进程之间（如父进程和子进程）进行单向通信。使用pipe() 系统调用来创建一个匿名管道，该函数返回一个文件描述符数组，其中一个描述符用于读取，另一个用于写入。当所有引用该管道的进程都退出时，匿名管道自动关闭。

2.信号

​ 信号是软件中断，可以用来通知进程发生了特定的事件。它们可以被用来中断进程的执行或者通知进程执行某些操作。

3.共享内存

​ 多个进程共享一块内存区域。进程可以通过映射这块内存区域来进行数据交换。
4.消息队列**

​ 消息队列是存储消息的链表，位于内核空间，可以被多个进程访问。进程可以通过消息队列发送和接收消息。

5.信号量

​ 信号量用于控制多个进程对共享资源的访问。它可以用来同步进程间的操作，防止多个进程同时访问同一资源。

6.Socket

​ Socket 可以分为流式 (TCP) 和数据报 (UDP) 类型。

线程同步

1.信号量

​ 信号量同样可以用于线程间同步，控制对共享资源的访问，避免竞态条件。

2.读写锁

​ 读写锁允许多个线程同时读取共享资源，但在写入时需要独占访问。这种锁可以提高并发读取的效率。

3.条件变量

​ 条件变量允许线程等待某个条件满足后才继续执行。它通常与互斥锁一起使用，用于协调线程间的活动。

4.互斥锁

​ 互斥锁是一种简单的锁定机制，确保一次只有一个线程可以访问共享资源。当一个线程获取了互斥锁后，其他试图获取该锁的线程会被阻塞。

5.自旋锁

​ 当一个线程试图获取一个已经被另一个线程持有的锁时，它会循环等待直到锁可用。自旋锁适用于短时间的锁定操作，以减少上下文切换带来的开销。

RTC

实时时钟(Real Time Clock，RTC)，本质是一个计数器，计数频率常为秒，专门用来记录时间.

​ 普通定时器无法掉电运行！

​ RTC特性

​ 1,能提供时间（秒钟数）

​ 2,能在MCU掉电后运行

​ 3，低功耗

​ 为了能够配置RTC，必须先解锁备份寄存器。RTC和后备寄存器不会被系统或电源复位源复位；当从待机模式唤醒时，也不会被复位。 后备寄存器可用于保存掉电时的数据。

DMA

DMA，全称Direct Memory Access，即直接存储器访问。DMA传输 将数据从一个地址空间复制到另一个地址空间。传输无需CPU直接控制传输，也没有中断处理方式那样保留现场和恢复现场过程，通过硬件为RAM和IO设备开辟一条直接传输数据的通道，使得CPU的效率大大提高

DMA优先级：仲裁器管理DMA通道请求分为两个阶段：软件阶段(1)、硬件阶段(2)

​ 第一阶段（软件阶段）：每个通道的优先级可在DMA_CCRx寄存器中设置，有四个等级：最高、高、中和低优先级。

​ 第二阶段（硬件阶段）：如果两个请求有相同软件优先级，较低编号的通道比较高编号的通道有较高的优先级。（大容量芯片中，DMA1控制器拥有高于DMA2控制器的优先级）

FreeRTOS

FreeRTOS 中的滴答中断和 PendSV

在 FreeRTOS 中，滴答中断和 PendSV 是两个重要的中断，它们共同作用于任务调度和时间管理。

  1. 滴答中断:
    • 配置：通过 configTICK_RATE_HZ 宏配置滴答中断的频率，默认为 100Hz（10ms）。
    • 实现：硬件定时器配置为每 10ms 产生一次中断，RTOS 内核在中断服务程序中更新任务延时计数器并检查是否需要进行任务切换。
  2. PendSV:
    • 触发：当任务状态发生变化时，RTOS 内核会设置 PendSV 请求标志。
    • 处理：硬件定时器在滴答中断之外提供 PendSV 中断，RTOS 内核在 PendSV 中断服务程序中进行上下文切换。

滴答中断和 PendSV 是RTOS中非常重要的机制，它们分别用于时间管理和任务调度。通过滴答中断定期唤醒RTOS内核，PendSV 则在任务状态发生变化时进行上下文切换，共同确保RTOS能够按照预定的顺序和时间运行任务。

在RTOS中，当需要进行任务调度时，通常会设置 PendSV 请求标志。PendSV 请求标志的作用是通知RTOS内核在下一个滴答中断（Tick Interrupt）时进行上下文切换

basepri

basepri 是一个与实时操作系统（RTOS）相关的概念，尤其在 ARM 架构的处理器中被广泛使用。basepri 是 “Base Priority” 的缩写，它是一个重要的机制，用于控制中断和任务调度的行为。

  • basepri 是一个寄存器，用于设置最低优先级的中断。
  • 作用：通过设置 basepri 的值，可以禁止优先级低于该值的所有中断。
